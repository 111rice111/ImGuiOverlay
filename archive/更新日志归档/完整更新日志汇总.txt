====== v2.49 更新日志 (2026-07-06) ======

【关键修复】持续锁敌不中断 + 走路同时自瞄 + 移除抖动机制

◆ 用户反馈
1. 自瞄效果不好, 稍微离开一点距离就不瞄准了
2. 希望持续瞄准, 走路时也要一直瞄
3. 不要加抖动机制

◆ 根因分析 (3 处停止追踪的代码路径)
1. 真实手指让权 → 走路时停止
   - 旧逻辑: Touch::GetFingerCount() > 0 → aim_slide_up 抬起让权 → 自瞄停
   - 用户走路时摇杆 finger=1, 触发让权, 自瞄完全不工作
   - 这正是"走路时不瞄"的根因

2. 死区内直接 return → 稍偏就停
   - 旧逻辑: dist < 15px 直接 return, 不再修正
   - 目标在屏幕中心 15px 内完全不追踪 → "稍微离开就不瞄"
   - 用户感知为"自瞄距离稍远就失效"

3. 漂移>80px 抬起重按 → 持续追踪间隙不修正
   - 旧逻辑: 漂移超 80px → aim_slide_up 抬起 → 下一帧重按
   - 持续追踪几秒后频繁抬起, 期间不修正 → 追踪不连续

◆ 修复方案
1. 移除"真实手指让权"机制 (核心)
   - slot 2 已与真实摇杆 slot 0 物理隔离(TypeA 用 slot 值作 Finger[] 索引,
     Upload 把 Finger[0]+Finger[2] 通过 SYN_MT_REPORT 分隔同时提交给游戏)
   - 自瞄与摇杆可在不同 slot 并行工作, 无需让权
   - 真实手指仅用于诊断显示, 不再干预自瞄
   - 效果: 走路按摇杆时自瞄持续锁敌

2. 死区改为衰减系数 (不再停止)
   - 旧: dist < deadzone 直接 return
   - 新: dist < deadzone 时 step 乘 (dist/deadzone) 衰减系数
     越接近中心修正越弱, 但不停止
   - 既持续追踪目标, 又避免中心 1-2px 抖动
   - 死区默认 15→5px (仅防 1-2px 抖动)

3. 漂移改为软回中 (不再抬起)
   - 旧: 漂移>80px → aim_slide_up 抬起 → 重按间隙不修正
   - 新: 偏离起手点>30px 时, 本帧 step 叠加 15% 回中分量
     既持续追踪目标, 又缓慢回中防漂移, 无抬起间隙

4. W2S 失败改为保持等待 (不再抬起)
   - 旧: W2S 失败 → aim_slide_up → 重按间隙不修正
   - 新: W2S 失败 → 手指保持当前位置不 move, 等待目标回屏
   - 连续失败 30 帧(~0.5秒)才彻底结束(防永久占 slot)

5. 默认参数优化
   - 平滑度 0.85→0.7 (系数 0.15→0.3, 更激进追踪, 减少延迟)
   - 死区 15→5px (仅防 1-2px 抖动, 不再"稍偏就停")
   - 最大追踪距离 30→50 米 (扩大追踪范围)

◆ 文件改动
- app/src/main/cpp/src/Android_draw/AutoAim.cpp (5 处核心修改)
- app/src/main/cpp/src/Android_draw/net_client.h (CURRENT_VERSION 248→249)

◆ 部署流程 (参照使用说明书)
1. adb push overlay_user /sdcard/overlay_user_tmp
2. su -c 'cp /sdcard/overlay_user_tmp /data/local/bin/overlay_user && chmod 777 ... && rm ...'
3. setsid 后台启动 (避免 ADB 断开 SIGHUP)

◆ 版本信息

◆ 验收测试
1. 开自瞄 → 走路按摇杆 → 视角应持续锁敌不中断
2. 目标在屏幕中心附近 → 仍持续微调(不再"稍偏就停")
3. 持续追踪 10 秒以上 → 不出现间隙性停顿

====== v2.50 更新日志 (2026-07-06) ======

【关键修复】真实手指落下时自瞄失效 → 直写 uinput 绕过 TypeA 链路

◆ 用户反馈
开自瞄后, 真实手指放到屏幕上时自瞄就失效了
W2S 没有失败, 滑动一直显示 ON, 目标一直 OK
即: 状态机正常运行, 但滑动没产生效果

◆ 根因分析 (TypeA + Upload() 的 SYN_MT_REPORT 链路缺陷)
旧注入链路:
  AutoAim write(/dev/input/eventX, slot=2)
    → 真实触摸屏 evdev 缓冲 (被 EVIOCGRAB)
    → TypeA 线程 read() 读到真实手指+自瞄事件混合流
    → SYN_REPORT 时 Upload() 提交, 只提交当前 latest 对应 Finger[]
    → 自瞄 pointer 被遗漏或 tracking_id 错乱
    → 真实手指落下时自瞄完全失效

关键问题:
1. 自瞄事件与真实手指事件混合在 TypeA 读取流
2. Upload() 用 SYN_MT_REPORT (Type A 协议) 顺序提交
3. 真实手指落下时 latest 变量在 slot 0/2 间切换
4. SYN_REPORT 只提交当前 latest 对应 Finger, 自瞄被遗漏

◆ 修复方案: 自瞄直写 uinput (nowfd), 绕过 TypeA/Upload
新注入链路:
  AutoAim → Touch::InjectAimTouch(screen_x, screen_y, tid, is_down)
    → 直接 write(nowfd, ev[], ...) 写 uinput 虚拟设备
    → Android InputReader 给 uinput 分配独立 deviceId
    → 真实手指(经 TypeA→Upload→nowfd, slot 0)与自瞄(slot 2)
       在 InputReader 层合并为合法多指 MotionEvent
    → 物理隔离, 真实手指落下时自瞄仍持续工作

◆ 文件改动
1. TouchHelperA.h
   - 新增 InjectAimTouch() 接口声明
2. TouchHelperA.cpp

     位置 + 压力 + 接触面积 + SYN_REPORT), 一次 write 原子提交
3. AutoAim.cpp
   - aim_slide_down/move/up 改为调用 Touch::InjectAimTouch
   - 删除 g_aim_touch_fd / aim_emit / aim_write_position (不再写真实设备)
   - 删除 aim_end_slide 中的 close(fd) (无 fd 需要 close)
4. net_client.h: CURRENT_VERSION 249→250

◆ 关键技术点
- uinput 已注册 ABS_MT_SLOT/TRACKING_ID/POSITION_X/Y (Init 中 UI_SET_ABSBIT)
- 自瞄用 slot 2, 真实手指经 Upload 提交 slot 0
- 一次 write 提交完整一帧 (slot + tracking_id + 位置 + 按键 + SYN_REPORT)
  避免半帧被 InputReader 消费导致指针错位
- 自瞄 tracking_id 从 1000 起步自增, 避免与真实手指低位 id 冲突

====== v2.51 更新日志 (2026-07-06) ======

【关键修复】真实手指落下时自瞄失效 → 仍走盖板路径,绕过 evdev 缓冲竞争

◆ 用户反馈
v2.49/v2.50: 开自瞄后真实手指放屏幕上, 自瞄就失效
W2S 没失败, 滑动 ON, 目标 OK, 但滑动没效果
v2.50 直写 uinput 被游戏过滤, 必须走盖板路径

◆ 根因分析 (write /dev/input/eventX 的 evdev 缓冲竞争)
旧链路 (v2.49):
  AutoAim write(/dev/input/eventX, slot=2)
    → 真实触摸屏 evdev 缓冲
    → TypeA read() 读到真实手指+自瞄事件混合流
    → SYN_REPORT → Upload() 提交到 nowfd

问题:
  真实手指落下时事件流密集 (slot 0 down + 多个 move)
  自瞄的 slot 2 事件被挤到后面读取
  Finger[2].pos 更新延迟或丢失 → Upload 提交旧值 → 自瞄失效

◆ 修复方案: 直接更新 Finger[2] + 调用 Upload() (仍是盖板路径)
新链路 (v2.51):
  AutoAim → Touch::InjectAimTouch(screen_x, screen_y, tid, is_down)
    → lock.lock()
    → 直接更新 devices[0].Finger[2].pos/isDown/id
    → 调用 Upload() (盖板路径: SYN_MT_REPORT 分隔 + write(nowfd))
    → lock.unlock()

关键点:
1. 仍走盖板路径: Upload 内部 write(nowfd), 提交格式与盖板一致
   → 不被反作弊过滤
2. 绕过 evdev 缓冲: 不再 write(/dev/input/eventX), 不与真实手指事件竞争
   → 真实手指落下时自瞄仍能立即更新 Finger[2]
3. Upload 遍历所有 isDown 的 Finger, 同时提交:
   - Finger[0] (真实摇杆 slot 0)
   - Finger[2] (自瞄 slot 2)
   游戏收到合法两指 MotionEvent, 互不冲突
4. lock 保护: AutoAim 的 Upload 与 TypeA 的 Upload 串行执行, 无并发写冲突

1. TouchHelperA.h: 新增 InjectAimTouch() 接口声明

【紧急修复】自瞄视角乱转/震荡问题

◆ 修复问题
自瞄开启后视角"一直乱换屏幕"——持续旋转或来回震荡无法稳定。

◆ 根因分析
1. 滑动位移过大导致 overshoot 震荡
   - 原代码: step = dx * (1 - smoothing), smoothing默认0.15 → 系数0.85
   - 目标偏离中心500px时, step=425px/帧
   - 限幅±80px → 80px/帧 = 4800px/秒 = 每秒滑4.4屏
   - 视角过度修正 → 目标跑到屏幕另一侧 → 反向修正 → 来回震荡

2. 虚拟手指位置无限累加漂移导致卡边界
   - 手指位置每帧累加 step, 永远不回中
   - 追踪几秒后手指贴在屏幕边界被 clamp 钉死
   - 视角持续向某方向转 → "一直乱换"

3. 死区内停止滑动但手指不回中
   - 目标进入死区时直接 return, 手指漂在偏离起手位置
   - 下一帧目标移出死区时基准点已错乱

◆ 修复方案
1. 默认平滑度 0.15 → 0.85（系数0.85→0.15, 位移缩小近6倍）
2. 单帧限幅 ±80px → ±12px（60fps下最大720px/秒, 消除overshoot）
3. 新增回中机制 AimSlideReturnHome():
   - 目标进入死区时手指以25%/帧速度回到起手位置
   - W2S失败/目标在屏幕外时同样回中
   - 回到起手位置3px内自动抬起手指
4. 死区默认 10px → 15px（减少边缘抖动）
5. UI Slider范围调整:

====== v2.48 更新日志 (2026-07-06) ======

【关键修复】自瞄与移动摇杆冲突 + 视角乱转/乱换屏幕

◆ 修复问题
1. 开启自瞄时按住移动摇杆, 角色移动会被打断
2. 自瞄开启后视角"乱换屏幕"持续旋转无法稳定
3. W2S 失败/目标出屏幕后手指回中导致反向旋转震荡

◆ 根因分析
1. 触摸点 ID 复用 slot 0
   - 旧实现 aim_slide_down 用 ABS_MT_SLOT=0, 与真实摇杆共用 slot 0
   - 自瞄 down 把摇杆 tracking_id 覆盖, 坐标被改写 → 角色停止/跳屏
2. 漂移回中 AimSlideReturnHome 引发极限环震荡
   - 偏离起手 80px 后每帧回拉 25% → 反向旋转视角 → 目标甩出屏幕中心
   - 重新检测偏差 → 正向追踪 → 再漂移 → 再回中 → 来回震荡 = "乱换屏幕"
3. W2S 失败时回中同样产生反向旋转

◆ 注入链路确认(模仿自动盖板)
自动盖板 SimulateClick 已验证可行, 其链路为:
  write(/dev/input/eventX) → EVIOCGRAB 只挡 read 不挡 write
  → TypeA 线程读到写入 → device.Finger[slot] 更新
  → Upload() 把所有 isDown 的 Finger 通过 SYN_MT_REPORT 分隔
  → 一次 SYN_REPORT 提交到 nowfd(uinput)
  → Android InputReader → 游戏 MotionEvent

  独立注册 input 设备(上轮方案)反而被游戏反作弊过滤, 因游戏只信任
  从真实触摸屏链路(uinput 重注入)来的事件. 故必须模仿盖板直写真实屏.

◆ 修复方案: slot 隔离 (关键)
  TypeA 用 ABS_MT_SLOT 值作为 device.Finger[] 索引
  Upload() 遍历 Finger[0..9] 把每个 isDown 通过 SYN_MT_REPORT 分隔提交

  因此自瞄改用 slot 2:
  - 真实摇杆 → slot 0 → Finger[0]
  - 第二真实指(技能) → slot 1 → Finger[1]
  - 自瞄 → slot 2 → Finger[2] (物理隔离, 不冲突)

  Upload() 一次性把 Finger[0]+Finger[2] 通过 uinput 提交给游戏
  → 游戏收到合法两指 MotionEvent, 摇杆与自瞄同时工作互不干扰

◆ 具体改动 (AutoAim.cpp, 6 处, 不新增文件/不改 TouchHelperA)
1. aim_slide_down: ABS_MT_SLOT 0→2, tracking_id 1→自增高位(1000+)
   每次 down 用新 id 防止游戏复用旧 pointer 状态
2. aim_slide_move: move 前重新指定 slot 2 (TypeA 每次读 ABS_MT_SLOT 才更新 latest)
3. aim_slide_up: slot 0→2, 抬起只影响自瞄不顶摇杆
4. W2S 失败: 移除 AimSlideReturnHome 回中, 改为直接 aim_slide_up
   抬起期间不施加位移, 视角不反向转, 下一帧目标回屏幕内自然重按
5. 漂移>80px: 移除回中滑动, 改为直接 aim_slide_up
   下一帧在起手点重按, 切断"追踪↔回中"极限环
6. 真实手指检测: 注释修正
   旧 slot 0 时 fingerCount-1 启发式错误(真实摇杆与自瞄合并为1个)
   新 slot 2 隔离后此启发式终于正确

====== v2.49 更新日志 (2026-07-06) ======

【关键修复】持续锁敌不中断 + 走路同时自瞄 + 移除抖动机制

◆ 用户反馈
1. 自瞄效果不好, 稍微离开一点距离就不瞄准了
2. 希望持续瞄准, 走路时也要一直瞄
3. 不要加抖动机制

◆ 根因分析 (3 处停止追踪的代码路径)
1. 真实手指让权 → 走路时停止
   - 旧逻辑: Touch::GetFingerCount() > 0 → aim_slide_up 抬起让权 → 自瞄停
   - 用户走路时摇杆 finger=1, 触发让权, 自瞄完全不工作
   - 这正是"走路时不瞄"的根因

2. 死区内直接 return → 稍偏就停
   - 旧逻辑: dist < 15px 直接 return, 不再修正
   - 目标在屏幕中心 15px 内完全不追踪 → "稍微离开就不瞄"
   - 用户感知为"自瞄距离稍远就失效"

3. 漂移>80px 抬起重按 → 持续追踪间隙不修正
   - 旧逻辑: 漂移超 80px → aim_slide_up 抬起 → 下一帧重按
   - 持续追踪几秒后频繁抬起, 期间不修正 → 追踪不连续

◆ 修复方案
1. 移除"真实手指让权"机制 (核心)
   - slot 2 已与真实摇杆 slot 0 物理隔离(TypeA 用 slot 值作 Finger[] 索引,
     Upload 把 Finger[0]+Finger[2] 通过 SYN_MT_REPORT 分隔同时提交给游戏)
   - 自瞄与摇杆可在不同 slot 并行工作, 无需让权
   - 真实手指仅用于诊断显示, 不再干预自瞄
   - 效果: 走路按摇杆时自瞄持续锁敌

2. 死区改为衰减系数 (不再停止)
   - 旧: dist < deadzone 直接 return
   - 新: dist < deadzone 时 step 乘 (dist/deadzone) 衰减系数
     越接近中心修正越弱, 但不停止
   - 既持续追踪目标, 又避免中心 1-2px 抖动
   - 死区默认 15→5px (仅防 1-2px 抖动)

3. 漂移改为软回中 (不再抬起)
   - 旧: 漂移>80px → aim_slide_up 抬起 → 重按间隙不修正
   - 新: 偏离起手点>30px 时, 本帧 step 叠加 15% 回中分量
     既持续追踪目标, 又缓慢回中防漂移, 无抬起间隙

4. W2S 失败改为保持等待 (不再抬起)
   - 旧: W2S 失败 → aim_slide_up → 重按间隙不修正
   - 新: W2S 失败 → 手指保持当前位置不 move, 等待目标回屏
   - 连续失败 30 帧(~0.5秒)才彻底结束(防永久占 slot)

5. 默认参数优化
   - 平滑度 0.85→0.7 (系数 0.15→0.3, 更激进追踪, 减少延迟)
   - 死区 15→5px (仅防 1-2px 抖动, 不再"稍偏就停")
   - 最大追踪距离 30→50 米 (扩大追踪范围)
